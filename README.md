# Лаборатори №6 — Category-Partition ба PICT

**Оюутан:** Оюунсүрэн Мөнхзолбоо  
**Оюутны код:** B210910878

## A. Category-Partition — Банкны шилжүүлэг

**Тестлэх тодорхойлолт:** `POST /transfer` — `{ "from": ID, "to": ID, "amount": NUM, "currency": CODE }`. Энэ лабораторид API код ажиллуулахгүй; оролтын ангилал, хязгаарлалт, хүлээгдэх үр дүнг тодорхойлно.

### A1. Сонголт ба төлөөлөх утгууд

Туршилтын орчин: `A001` — идэвхтэй, царцаагдаагүй, MNT данс; үлдэгдэл 1,000,000 MNT, өдрийн ашиглах боломжтой лимит 500,000 MNT. `A002` — өөр хүний идэвхтэй MNT данс. `A003` — царцаагдсан данс. `A004` — идэвхтэй USD данс. `X999` — байхгүй данс. Хөрвүүлэлтийн жишээнд **зөвхөн тестийн өгөгдөл болгон** `1 USD = 3,500 MNT` гэж үзэв; бодит банкны ханш гэж ойлгохгүй.

| Категори | Сонголт | Төлөөлөх утга / тайлбар | Тэмдэглэгээ |
|---|---|---|---|
| From | Valid | `A001`, хүчинтэй, царцаагдаагүй | Энгийн |
| From | Frozen | `A003`, царцаагдсан | `[ERROR]` |
| From | Missing | `X999`, данс байхгүй | `[ERROR]` |
| To | Valid | `A002`, илгээгчээс өөр хүчинтэй данс | Энгийн |
| To | Missing | `X999`, хүлээн авагч байхгүй | `[ERROR]` |
| To | SameAsFrom | `A001` (`from=A001` үед) | `[ERROR] [IF From=Valid]` |
| Amount | Zero | `0` | `[ERROR]` |
| Amount | Negative | `-1` | `[ERROR]` |
| Amount | Normal | `100,000 MNT` | Энгийн |
| Amount | OverBalance | `1,100,000 MNT` (үлдэгдэл 1,000,000) | `[ERROR] [IF From=Valid]` |
| Amount | OverLimit | `600,000 MNT` (үлдэгдэл хүрэлцээтэй, лимит 500,000) | `[ERROR] [IF From=Valid]` |
| Currency | Same | `MNT`, дансны валюттай ижил | Энгийн |
| Currency | Different | `USD`, илгээгчийн дансны валютаас өөр | `[IF From=Valid]` |

**Далд орчны нөхцөл:** Илгээгчийн үлдэгдэл, тухайн өдрийн өмнө хийсэн шилжүүлгүүдээс хамаарах үлдсэн лимит, дансны валют, валютын ханш нь хүсэлтийн JSON-д байхгүй боловч үр дүнд нөлөөлнө. Эдгээрийг setup-д тогтмол тодорхойлж, `OverBalance`, `OverLimit`, `Different` сонголтуудаар төлөөлүүлэв. Ханшийн хөрвүүлэлтийн дараах дүнгээр үлдэгдэл болон лимитийг шалгана.

### A2. Хязгаарлалт, үндэслэл ба тооцоо

**Алдааны давуу эрэмбэ (тестийн таамаглал):** `ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT`. Учир нь эхлээд дансуудын хүчинтэй байдлыг, дараа нь мөнгөн дүн болон санхүүгийн хязгааруудыг шалгах нь тестийн хүлээгдэх үр дүнг тогтвортой тодорхойлоход тохиромжтой. Энэ эрэмбийг өгөгдсөн API тодорхойлолт заагаагүй тул хэрэгжүүлэлттэй тулгаж баталгаажуулаагүй.

- `[ERROR]`: дангаар нь шалгахад тодорхой алдаа өгөх хүчингүй сонголт; өөр алдаатай давхардах үед дээрх давуу эрэмбийг хэрэглэнэ.
- `[IF]`: утга зөвхөн тодорхой орчинд утгатай. Жишээлбэл `SameAsFrom`-ийг `From=Valid` үед, `OverBalance` болон `OverLimit`-ийг хүчинтэй илгээгчийн үлдэгдэл, лимит тогтоосон үед шалгана.
- `[SINGLE]`: валютын хөрвүүлэлтийн заагийг шалгах **тусгай нэг тест** (`S01`-ээс тусад нь `S12`); зөвхөн нэг удаа тусгайлан оруулна. `[SINGLE]` нь энд PICT-ийн бүх мөрөөс автоматаар хасах дүрэм биш, гараар сонгосон онцгой тест юм.

**Бүрэн олонлог:** `From(3) × To(3) × Amount(5) × Currency(2) = 90` боломжит ангиллын хослол.

**Гараар сонгосон хязгаарлалт:** `From ≠ Valid` үед `To=SameAsFrom`, `Amount=OverBalance/OverLimit`, `Currency=Different`-ийг хасна. `From=Valid` үед бүх сонголтыг үлдээнэ. Иймд:

- `From=Valid`: `1 × 3 × 5 × 2 = 30`
- `From=Frozen` эсвэл `Missing`: `2 × 2 × 3 × 1 = 12`
- **`90 → 48`** (тодорхойлсон нийцлийн хязгаарлалтуудын дараа).

Энэ нь бүх боломжит бодит банкны нөхцөлийн тоо биш, зөвхөн дээр тодорхойлсон категориудын загварын тоо юм. `[ERROR]`-ийг нэг мөрд хамгийн ихдээ нэгээр зөвшөөрөх тусгай дүрэм нэмбэл тоо өөрчлөгдөнө; PICT-ийн `~` хувилбарт үүнийг тусад нь харьцуулна.

### A3. Тестийн спецификацийн хүснэгт

Доорх `Amount` утгууд нь илгээгчийн валют руу хөрвүүлсний дараах шалгалтыг төлөөлнө. Давхар алдаатай мөрүүдэд A2-ын давуу эрэмбийг ашигласан. `S12`-ын USD дүн нь зөвхөн загварын ханшаар тооцсон жишээ.

| ID | From | To | Amount | Currency | Хүлээгдэх статус ба үр дүн |
|---|---|---|---|---|---|
| S01 | Valid | Valid | Normal | Same | `201 {"result":"OK"}` |
| S02 | Missing | Valid | Normal | Same | `200 {"result":"ERROR_NO_FROM"}` |
| S03 | Frozen | Valid | Normal | Same | `200 {"result":"ERROR_FROZEN"}` |
| S04 | Valid | Missing | Normal | Same | `200 {"result":"ERROR_NO_TO"}` |
| S05 | Valid | SameAsFrom | Normal | Same | `200 {"result":"ERROR_SAME_ACCOUNT"}` |
| S06 | Valid | Valid | Zero | Same | `200 {"result":"ERROR_BAD_AMOUNT"}` |
| S07 | Valid | Valid | Negative | Same | `200 {"result":"ERROR_BAD_AMOUNT"}` |
| S08 | Valid | Valid | OverBalance | Same | `200 {"result":"ERROR_INSUFFICIENT"}` |
| S09 | Valid | Valid | OverLimit | Same | `200 {"result":"ERROR_LIMIT"}` |
| S10 | Frozen | Missing | Zero | Same | `200 {"result":"ERROR_FROZEN"}` — давхар алдаа, эхний шалгалт |
| S11 | Valid | Missing | OverBalance | Same | `200 {"result":"ERROR_NO_TO"}` — давхар алдаа, хүлээн авагчийг түрүүлж шалгана |
| S12 | Valid | Valid | Normal (`100 USD = 350,000 MNT`) | Different | `201 {"result":"OK"}` — `[SINGLE]`, ханшийн хөрвүүлэлт |

**Тайлбар:** `S01` нь happy path; `S02–S09` нь тодорхойлолтод өгсөн бүх алдааны ангийг хамарна; `S10–S11` нь олон алдааны давуу эрэмбийг; `S12` нь хөрвүүлэлтийн тусгай нөхцөлийг шалгана. `S12`-ын 350,000 MNT нь 1,000,000 MNT үлдэгдэл, 500,000 MNT үлдсэн лимитийн аль алинд багтана.

## B. PICT — Pairwise covering array

### B1. Browser загварын үр дүн

| Туршилтын арга | Тестийн тоо | Бүрэн хувилбараас буурсан хувь |
|---|---:|---:|
| Бүх боломжит хослол | 144 | 0% |
| PICT 2-way | 10 | 93.1% |
| PICT 3-way | 20 | 86.1% |

PICT-ийн 2-way загвар нь параметрүүдийн бүх хос утгыг хамруулахыг зорьдог. Харин 3-way загвар нь гурван параметрийн утгын хослолуудыг хамардаг тул илүү олон тест үүссэн.

PICT нь greedy алгоритм ашигладаг учраас хамгийн цөөн мөртэй тестийн багцыг заавал гаргахгүй.

### B2. Transfer загваруудын харьцуулалт

| Загвар               | PICT тестийн тоо | Happy path | Нэг мөр дэх хамгийн их алдаа |                     Тайлбар                          |
|----------------------|-----------------:|-----------:|-----------------------------:|------------------------------------------------------|
| `transfer-nc.model`  |        15        |     0      |              3               | Хязгаарлалтгүй, олон алдаа давхардах боломжтой       |
| `transfer.model`     |        13        |     0      |              3               | Нийцлийн хязгаарлалттай боловч алдаа давхардаж болно |
| `transfer-neg.model` |        18        |     2      |              1               | `~` тэмдэглэгээтэй, сөрөг сонголтуудыг тусгаарласан  |

`transfer-nc.model` нь хязгаарлалтгүй тул нэг мөрөнд гурван алдаа зэрэг тохиолдсон. `transfer.model` нь зарим боломжгүй хослолыг хязгаарласан боловч нэг мөрөнд гурван алдаа давхардах боломжтой хэвээр байна. Харин `transfer-neg.model`-ийн 18 мөрөөс 2 нь happy path, үлдсэн 16 нь тус бүр нэг сөрөг сонголттой байв. `~` тэмдэглэгээ нь сөрөг сонголтуудыг тусгаарлахад тусалдаг боловч дансны нийцлийн хязгаарлалтуудыг орлохгүй.

A2 хэсгийн 90 → 48 тооцоо нь гараар тодорхойлсон хязгаарлалтад хамаарна. PICT-ийн `transfer.model` болон `transfer-neg.model` файлуудын хязгаарлалт үүнээс өөр тул 48-ыг эдгээр файлын боломжит хослолын тоо гэж үзэхгүй.

### B3. PICT-ийн үр дүнгээс сонгосон бодит тестүүд

**TC01 — Амжилттай шилжүүлэг**

- PICT: Valid / Valid / Normal / Same
- Өгөгдөл: A001 идэвхтэй, үлдэгдэл 500000 MNT, өдрийн лимитийн үлдэгдэл 300000 MNT. A002 данс байгаа.
- Request: `{"from":"A001","to":"A002","amount":100000,"currency":"MNT"}`
- Expected: `201 {"result":"OK"}`

**TC02 — Үлдэгдэл хүрэлцэхгүй**

- PICT: Valid / Valid / ~OverBalance / Different
- Өгөгдөл: A001 үлдэгдэл 50000 MNT, A002 байгаа. Жишээ ханш 1 USD = 3500 MNT, өдрийн лимит хүрэлцээтэй.
- Request: `{"from":"A001","to":"A002","amount":100,"currency":"USD"}`
- Expected: `200 {"result":"ERROR_INSUFFICIENT"}`

**TC03 — Илгээгч данс байхгүй**

- PICT: ~Missing / Valid / Normal / Same
- Өгөгдөл: A999 данс байхгүй, A002 данс байгаа.
- Request: `{"from":"A999","to":"A002","amount":100000,"currency":"MNT"}`
- Expected: `200 {"result":"ERROR_NO_FROM"}`

### Дүгнэлт

### Дүгнэлт

Энэ лабораторийн ажлаар Category-Partition болон PICT аргуудыг ашиглан банкны шилжүүлгийн тестүүдийг боловсруулав.

Category-Partition аргаар оролтын нөхцөлүүдийг ангилж, хүчинтэй болон алдаатай утгуудыг тодорхойлсон.

Гараар тест зохиохын давуу тал нь алдааны шалтгаан, шалгах дараалал болон хүлээгдэх үр дүнг нарийн тодорхойлох боломжтой байдаг.

Гэхдээ олон параметртэй үед бүх хослолыг гараар шалгах нь цаг их шаарддаг бөгөөд зарим хослолыг орхигдуулах эрсдэлтэй.

PICT нь параметрүүдийн утгын хос бүрийг хамарсан тестүүдийг автоматаар үүсгэдгээрээ давуу талтай.

Browser загварт 144 боломжит хослол байснаас PICT 2-way аргаар 10, 3-way аргаар 20 тест үүсгэсэн.

Банкны шилжүүлгийн хязгаарлалттай PICT загвараас 13 тест гарсан боловч эдгээрт happy path мөр ороогүй байв.

Харин `~` тэмдэглэгээтэй загвараас 18 тест үүсэж, хоёр happy path мөр болон тус бүр нэг сөрөг сонголттой 16 мөр гарсан.

PICT-ийн сул тал нь алдааны зөв хариу болон бизнесийн дүрмийг өөрөө тодорхойлдоггүй тул Category-Partition-ийн шинжилгээ шаардлагатай байдаг.

Миний хувьд хамгийн их бодож ажилласан хэсэг нь хязгаарлалтуудыг зөв тодорхойлж, олон алдаа давхцах үед аль алдааг түрүүлж шалгахыг шийдэх явдал байв.

## Үр дүнг дахин гаргах заавар

Энэ лабораторийн PICT загваруудыг MSYS2 UCRT64 орчинд ажиллуулсан. PICT хэрэгслийг эх кодоос хөрвүүлсэн бөгөөд ашигласан commit болон usage мэдээллийг `results/pict-build.txt` файлд хадгалсан.

Репозиторыг татаж авсны дараа PICT хэрэгслийг суулгасан орчинд төслийн үндсэн хавтсаас дараах командуудыг ажиллуулна.

```bash
pict browser.model > results/browser-2way.txt
pict browser.model /o:3 > results/browser-3way.txt
pict transfer-nc.model > results/transfer-nc.txt
pict transfer.model > results/transfer.txt
pict transfer-neg.model > results/transfer-neg.txt
```

MSYS2 UCRT64 орчинд `/o:3` сонголтыг ашиглахдаа замын автомат хөрвүүлэлтийг идэвхгүй болгоно.

```bash
MSYS_NO_PATHCONV=1 pict browser.model /o:3 > results/browser-3way.txt
```

`pict` команд PATH-д байхгүй бол өөрийн суулгасан PICT executable-ийн замыг ашиглана. Энэ лабораторид `~/tools/pict/pict` замыг хэрэглэсэн.

Гаралтын эхний мөр нь параметрийн нэрсийг агуулдаг тул тестийн тоог шалгахдаа нэг мөрийг хасна.

| Үр дүнгийн файл | Хүлээгдэх тестийн тоо |
|---|---:|
| `results/browser-2way.txt` | 10 |
| `results/browser-3way.txt` | 20 |
| `results/transfer-nc.txt` | 15 |
| `results/transfer.txt` | 13 |
| `results/transfer-neg.txt` | 18 |

PICT нь ижил хамрах хүрээг хангах өөр мөрүүд үүсгэж болох тул үр дүнгийн мөр бүрийг үгчлэн харьцуулахын оронд тестийн тоо болон хамрах хүрээг шалгана.
